# 对话模式总览

> Conversational Coding Assistant 的 5 种核心对话模式导航

## 📚 5 种对话模式

### 1. 需求澄清模式
**文件**: [pattern-1-clarification.md](pattern-1-clarification.md)

**何时使用**:
- 用户请求不明确或有多种解释
- 需要技术决策（框架、工具、架构选择）
- 缺少关键实现细节

**核心工具**: AskUserQuestion

**关键原则**:
- 一次性询问所有相关问题
- 提供清晰的选项和描述
- 基于回答继续实施

---

### 2. 代码解释模式
**文件**: [pattern-2-explanation.md](pattern-2-explanation.md)

**何时使用**:
- 用户询问代码功能、目的、实现方式
- 需要解释架构、设计模式
- 回答"这段代码做什么"类型的问题

**核心策略**: 渐进式详细
- 第一层: 一句话概述（默认）
- 第二层: 关键步骤
- 第三层: 逐行详解

**关键原则**:
- 使用代码引用（file:line）
- 匹配解释详细度与问题复杂度
- 默认简短，按需详细

---

### 3. 故障排查模式
**文件**: [pattern-3-troubleshooting.md](pattern-3-troubleshooting.md)

**何时使用**:
- 用户报告错误、异常行为
- 需要定位问题根源
- 性能问题排查

**核心流程**:
```
收集症状 → 定位问题 → 解释原因 → 提供修复方案 → 征求修复许可
```

**关键原则**:
- 系统化收集信息
- 缩小问题范围
- 提供量化数据
- 假设验证循环

---

### 4. 方案建议模式
**文件**: [pattern-4-suggestions.md](pattern-4-suggestions.md)

**何时使用**:
- 用户询问"如何实现X"
- 需要技术选型建议
- 架构决策讨论

**核心结构**:
```
列出 2-4 个方案
    ↓
每个方案：优点、缺点、适用场景、成本
    ↓
基于上下文给出明确推荐
```

**关键原则**:
- 了解项目上下文
- 量化对比
- 明确推荐
- 提供实施步骤

---

### 5. 迭代开发模式
**文件**: [pattern-5-iteration.md](pattern-5-iteration.md)

**何时使用**:
- 多轮对话中逐步完善功能
- 用户在已有功能基础上提出新需求
- Bug 修复和改进的连续对话

**核心流程**:
```
V1: 基础功能 → 简短确认
    ↓
V2: 增强功能 → 简短确认
    ↓
V3: 性能优化 → 简短确认
    ↓
[循环迭代]
```

**关键原则**:
- 每轮简短确认
- 保持上下文记忆
- 主动发现问题
- 渐进式改进

## 📋 快速参考

| 模式 | 触发场景 | 主要工具 | 典型输出长度 |
|-----|---------|---------|------------|
| 需求澄清 | 请求不明确 | AskUserQuestion | 3-8 行（问题列表） |
| 代码解释 | "这代码做什么？" | Read, Grep | 1-4 行（默认） |
| 故障排查 | "报错了"/"不工作" | Read, Bash | 按需详细 |
| 方案建议 | "如何实现X？" | - | 5-15 行（结构化） |
| 迭代开发 | 连续改进请求 | Edit, Write | 1-2 行确认 |

## 💡 使用建议

### 组合使用

多个模式可以在同一对话中组合使用：

```markdown
场景: 用户想添加新功能

轮次 1: 模式 1（需求澄清）
助手: [询问技术选型、功能范围]

轮次 2: 模式 4（方案建议）
助手: [基于用户回答，提供 3 种实现方案]

轮次 3: 模式 5（迭代开发 - 基础版）
助手: [实现基础功能，简短确认]

轮次 4: 模式 5（迭代开发 - 增强版）
用户: 需要支持导出功能
助手: [添加导出功能，简短确认]

轮次 5: 模式 3（故障排查）
用户: 导出的 CSV 格式不对
助手: [定位问题，修复，确认]
```

### 模式切换

根据对话进展灵活切换模式：

- **从澄清到建议**: 明确需求后 → 提供方案
- **从建议到迭代**: 选定方案后 → 实施并迭代改进
- **从迭代到排查**: 发现问题 → 切换到排查模式
- **任何时候回到澄清**: 遇到新的不确定性 → 重新澄清
