## 🔍 任务分解策略

**完整指南**: [任务分解模式](resources/task-breakdown-patterns.md)

### 快速参考

#### 1. SMART 原则

每个任务应该是：
- **S**pecific（具体的）- 明确做什么
- **M**easurable（可衡量的）- 能判断是否完成
- **A**chievable（可实现的）- 单次执行可完成
- **R**elevant（相关的）- 与总目标直接相关
- **T**ime-bound（有时限的）- 明确何时完成

#### 2. 分解层次

```
复杂任务
    ↓
【第一层分解】按功能模块
    ↓
【第二层分解】按实施步骤
    ↓
【第三层分解】按文件/函数
```

**示例**:
```markdown
任务: "实现用户管理系统"

第一层（模块级）:
1. 设计数据模型
2. 实现后端 API
3. 创建前端界面
4. 添加测试

第二层（步骤级 - 以"实现后端 API"为例）:
2.1 创建用户 CRUD 端点
2.2 添加认证中间件
2.3 实现权限验证
2.4 添加 API 文档

第三层（执行级 - 以"创建用户 CRUD 端点"为例）:
2.1.1 创建 User model（src/models/user.ts）
2.1.2 实现 GET /users 端点
2.1.3 实现 POST /users 端点
2.1.4 实现 PUT /users/:id 端点
2.1.5 实现 DELETE /users/:id 端点
```

#### 3. 依赖识别

```markdown
任务依赖关系标识:

A → B → C    # 顺序依赖（A完成后才能做B）
A ⟹ B       # B 依赖 A 的输出
A ∥ B ∥ C   # 并行任务（可同时执行）
```
