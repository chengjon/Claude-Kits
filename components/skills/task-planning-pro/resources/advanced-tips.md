## 🚨 常见陷阱

### 陷阱 1: 任务粒度过大

```markdown
❌ 粗粒度任务:
- "实现整个认证系统"           # 太大，无法衡量进度

✅ 合适粒度:
- "创建 User model"
- "实现登录 API"
- "添加 JWT token 生成"
- "创建登录表单"
- "编写认证测试"
```

### 陷阱 2: 任务粒度过小

```markdown
❌ 过细粒度:
- "导入 bcrypt 库"
- "创建 hashPassword 函数"
- "添加 return 语句"           # 太细，产生噪音

✅ 合适粒度:
- "实现密码哈希功能（bcrypt）"  # 包含导入和函数实现
```

### 陷阱 3: 模糊的任务描述

```markdown
❌ 模糊描述:
- "处理用户相关的事情"
- "修复那个 bug"
- "优化性能"

✅ 清晰描述:
- "实现用户注册 API（POST /auth/register）"
- "修复登录页面在 Safari 上的布局问题"
- "优化用户列表查询：添加索引，减少响应时间"
```

### 陷阱 4: 忘记更新状态

```markdown
❌ 常见错误:
[开始任务1]
[完成任务1]
[开始任务2]        ← 忘记标记任务1为completed
[完成任务2]
[批量更新]         ← 延迟更新，用户看不到实时进度

✅ 正确流程:
[标记任务1为 in_progress]
[执行任务1]
[标记任务1为 completed]    ← 立即更新
[标记任务2为 in_progress]
[执行任务2]
[标记任务2为 completed]    ← 立即更新
```

## 📊 决策树

### 何时创建 Todo 列表？

```
收到用户请求
    ↓
需要多少步骤完成？
    ↓
    ├─ 1步？ → 直接执行，无需 TodoWrite
    ├─ 2步？ → 简单任务，可选使用 TodoWrite
    └─ 3+步？→ 必须使用 TodoWrite
         ↓
    任务是否复杂？
         ↓
    ├─ 简单（如连续的文件操作）
    │   → 创建 3-5 个任务
    │
    └─ 复杂（如功能开发、重构）
        → 创建 5-10 个任务
             ↓
        是否有并行可能？
             ↓
        ├─ 是 → 分组标识（阶段1、阶段2）
        └─ 否 → 线性排列
```

### 任务粒度决策

```
考虑因素：
    ↓
1. 能否在 1-3 分钟内完成？
   ├─ 是 → ✅ 粒度合适
   └─ 否 → ❌ 需要进一步拆分
    ↓
2. 完成标准是否明确？
   ├─ 是 → ✅ 描述清晰
   └─ 否 → ❌ 需要细化描述
    ↓
3. 是否是原子操作？
   ├─ 是 → ✅ 不可再分
   └─ 否 → ❌ 继续分解
```

## 💡 高级技巧

### 技巧 1: 动态调整任务列表

```markdown
场景：执行中发现新问题

初始任务:
- [completed] 实现登录 API
- [in_progress] 添加单元测试
- [pending] 更新文档

发现问题：测试失败，需要修复 token 验证

调整任务列表:
- [completed] 实现登录 API
- [completed] 添加单元测试（发现问题）
- [in_progress] 修复 token 验证逻辑     ← 新增
- [pending] 重新运行测试套件             ← 新增
- [pending] 更新文档
```

### 技巧 2: 任务分组（使用描述性前缀）

```markdown
TodoWrite([
  // 阶段1: 调研
  { content: "【调研】搜索现有认证代码", ... },
  { content: "【调研】分析第三方库选项", ... },

  // 阶段2: 设计
  { content: "【设计】设计 token 流程", ... },
  { content: "【设计】定义 API 接口", ... },

  // 阶段3: 实施
  { content: "【实施】创建认证中间件", ... },
  { content: "【实施】实现登录端点", ... },

  // 阶段4: 验证
  { content: "【验证】运行集成测试", ... },
  { content: "【验证】手动测试各场景", ... }
])
```

### 技巧 3: 依赖标注

```markdown
任务描述中明确依赖:

✅ 清晰依赖:
- "创建数据库 schema"
- "实现 API 端点（依赖：schema 完成）"
- "添加前端调用（依赖：API 完成）"
- "编写端到端测试（依赖：前后端完成）"
```
