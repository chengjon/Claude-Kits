## 基准测试 1: 信息收集

### 场景: 分析项目认证实现

**任务**: 理解整个认证流程，包括前端表单、API路由、JWT处理、数据库操作

#### 顺序执行（Sequential）

```
1. Search "authentication"          → 1.2s
2. Read auth.service.ts             → 0.8s
3. Search "JWT token"               → 1.1s
4. Read jwt.utils.ts                → 0.7s
5. Grep middleware                  → 1.0s
6. Read auth.middleware.ts          → 0.8s
7. Search "login handler"           → 1.2s
8. Read auth.controller.ts          → 0.9s
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
总计: 7.7 秒（8 轮次）
```

#### 并行执行（Parallel）

```
轮次 1 (并行 4 个):
[
  codebase_search("authentication flow"),
  codebase_search("JWT token handling"),
  grep("middleware.*auth", type="ts"),
  glob("**/auth*.ts")
]                                   → 1.3s

轮次 2 (基于结果，并行 4 个文件):
[
  Read('auth.service.ts'),
  Read('jwt.utils.ts'),
  Read('auth.middleware.ts'),
  Read('auth.controller.ts')
]                                   → 0.9s
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

```

## 性能优化建议

### 1. 批次大小优化

```python
# 测试数据：不同批次大小的性能

批次大小 1:  总耗时 = n × 0.7s
批次大小 3:  总耗时 = n/3 × 0.9s   ✅ 推荐
批次大小 5:  总耗时 = n/5 × 1.0s   ✅ 推荐
批次大小 8:  总耗时 = n/8 × 1.2s   ✅ 推荐
批次大小 15: 总耗时 = n/15 × 1.8s
批次大小 20: 总耗时 = n/20 × 2.5s

推荐批次大小: 5-10 个工具调用
```

### 2. 工具选择优化

```markdown
| 任务类型 | 慢速方案 | 快速方案 | 提升 |
|---------|---------|---------|------|
| 精确符号查找 | codebase_search | grep | 2x |
| 文件名查找 | list_dir 递归 | glob | 3x |
| 已知文件读取 | search + read | 直接 read | 2x |
| 多文件读取 | 顺序 read | 并行 read | 4x |
```

### 3. 网络优化

```
单次工具调用延迟: ~250ms
  - 网络往返: 150ms
  - 服务器处理: 100ms

并行 8 个工具调用:
  - 顺序执行: 8 × 250ms = 2000ms
  - 并行执行: max(250ms) = 250ms
  - 提升: 8x
```

## 局限性说明

### 1. 上下文窗口限制

```markdown
并行读取过多文件可能导致上下文溢出
- 推荐: 每批 5-10 个文件
- 如果需要更多: 分批处理
```

### 2. 依赖关系场景

```markdown
某些任务天然是顺序的:
- 配置驱动的动态操作
- 条件分支逻辑
- 累积状态计算

这些场景无法并行，性能提升有限
```

### 3. 工具限制

```markdown
某些工具本身就很快 (< 100ms):
- 简单的 glob 查询
- 小文件读取

这些场景并行化收益较小
```
